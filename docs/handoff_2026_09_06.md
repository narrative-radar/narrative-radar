# Project Tycho — Technical Handoff
**Date**: September 6, 2026
**Status**: Ready for Production Deployment

## 1. Project Overview
Tycho is a macro-narrative radar for the Solana ecosystem (specifically Pump.fun tokens). It operates on a **continuous background processing architecture** rather than synchronous on-demand analysis. 

The system automatically ingests new tokens, generates vector embeddings via Google's Gemini API, and clusters them into narrative themes using mathematical similarity.

## 2. Core Architecture & Security
Following strict security audits, the application enforces the following rules:

* **No Public DB Writes**: The public token lookup endpoint (`/api/tokens/[mint]/cluster`) is 100% read-only (Cache-First). It does not write to the database or rely on external APIs like DexScreener.
* **Cron-Protected Ingestion**: The heavy lifting (Database Writes, LLM API calls) happens strictly in `/api/cron/cluster`, which is secured by `CRON_SECRET`.
* **Cost/Limit Optimized**: Embedding calls to Gemini (`gemini-embedding-2`) utilize `batchEmbedContents`. A 5-minute cron interval equates to ~288 requests/day, cleanly fitting within Gemini's Free Tier quotas.

## 3. The 3-State Token Lookup UI
When a user pastes a Contract Address (CA) on the dashboard, the system responds in one of three states instantly:
1. **🟢 Found (Clustered)**: Token exists and is clustered. Returns theme name and growth rate.
2. **🟡 Processing (On Radar Queue)**: Token has been ingested by the cron job but is awaiting LLM embedding/clustering. UI shows a pulsing yellow dot.
3. **⚪ Not Found**: Token is invalid or too new to have been caught by the radar. Gracefully asks the user to check back later.

## 4. Environment Variables Setup
To run Tycho in production, the following environment variables **MUST** be set in the Vercel Dashboard before deployment:

| Variable | Description |
|---|---|
| `DATABASE_URL` | Transaction-mode pooler string from Supabase (IPv4-only). |
| `GEMINI_API_KEY` | Google AI Studio key. Ensure quota for `gemini-embedding-2` is >288 RPD. |
| `CRON_SECRET` | A secure, random string (e.g., `KunciRadarTycho2026`). Must match the cron-job.org Bearer token. |

## 5. Deployment Workflow
1. Update local `.env` if testing locally.
2. Log in to Vercel and input the exact Environment Variables into the Project Settings.
3. Run `bunx vercel --prod` in the terminal.
4. Set up an external cron service (e.g., cron-job.org) to ping `https://<YOUR_VERCEL_DOMAIN>.vercel.app/api/cron/cluster` every 5 minutes.
5. In the cron service, add the HTTP Header: `Authorization: Bearer <YOUR_CRON_SECRET>`.

## 6. Next Steps & Post-Launch
* **Threshold Tuning**: The clustering similarity threshold is currently initialized at `0.85` in `clustering.service.ts`. Monitor how clusters form on production data and adjust this threshold tighter or looser as needed.
* **Vercel Hobby Limits**: The free tier restricts serverless function execution to 10 seconds. The `pumpfun.service.ts` uses an `AbortSignal` to prevent hanging, ensuring the cron fails gracefully rather than crashing the deployment.
